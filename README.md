# Planner

Десктопный планировщик задач на **PySide6 + Qt Quick/QML** с автоматической
двусторонней синхронизацией с Google Calendar.

Основной пакет — [`planner_desktop/`](planner_desktop/). Единственная точка
входа — [`run_desktop.py`](run_desktop.py).

> Прежняя реализация на Flet (`main.py`, `core/`, `storage/`, `ui/`,
> `models/`, `services/`) **удалена** из репозитория вместе со своим
> sync-контуром, тестами и документацией. Её профиль данных
> (`<user data dir>/Planner`) приложение никогда не читает и не изменяет.

## Запуск

### Windows

Дважды кликните `start_planner.bat` в Проводнике.

Лаунчер сам выбирает интерпретатор (`.venv\Scripts\python.exe` → `py -3` →
`python`), проверяет, что установлен PySide6, и запускает `run_desktop.py`.
Окно остаётся открытым только если запуск завершился ошибкой.

### Любая ОС

```bash
python run_desktop.py
```

## Установка

```bash
python -m venv .venv
# Windows
.venv\Scripts\python.exe -m pip install -r requirements.txt
# Linux / macOS
.venv/bin/python -m pip install -r requirements.txt
```

Нужен Python 3.11+. Зависимости — [`requirements.txt`](requirements.txt)
(runtime) и [`requirements-dev.txt`](requirements-dev.txt) (тесты).

## Тесты

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q                      # весь набор
python -m pytest tests/test_desktop_recurrence_service.py -q   # один файл
```

Тесты не ходят в сеть, не читают реальный профиль и не вызывают Google API:
календарные сценарии работают через `FakeCalendarGateway`, хранилище — через
временные каталоги.

## Где лежат данные

Приложение хранит данные **вне репозитория**, в отдельном профиле
пользователя:

| Что | Где |
|---|---|
| Каталог профиля | `<user data dir>/PlannerDesktop` (Windows — `%APPDATA%\PlannerDesktop`) |
| База данных | `<профиль>/app_desktop.db` |
| Настройки интерфейса | `<профиль>/preferences.json` |
| Черновики незавершённых форм | `<профиль>/drafts.json` |
| OAuth-токен | `<профиль>/token.json` |
| OAuth client secret | `<профиль>/secrets/client_secret.json` |

Путь профиля переопределяется переменной окружения
`PLANNER_DESKTOP_DATA_DIR` — так запускаются изолированные тестовые и
smoke-профили.

## Повседневная работа

- **Настройки интерфейса.** Можно выбрать стартовую страницу («Сегодня»,
  «Календарь» или последняя открытая), рабочие часы календаря и длительность
  новой задачи. Размер окна, вид и фильтр календаря запоминаются автоматически.
  Статистика выполнения на «Сегодня» включена по умолчанию; её можно скрыть
  переключателем в настройках.
- **Черновики.** Незавершённый текст быстрого добавления и поля редактора
  сохраняются отдельно от задач и восстанавливаются при следующем открытии,
  в том числе после перезапуска. Закрытие редактора не применяет правки к
  задаче. «Сбросить черновик» удаляет незавершённые правки; после успешного
  сохранения формы черновик очищается. Черновики не отправляются в Google.
- **Отмена действий.** `Ctrl+Z` вне текстового поля и диалога, кнопка «Отменить»
  и действие в уведомлении отменяют создание, редактирование, перенос,
  выполнение и удаление обычных задач, включая массовые изменения. Хранятся
  последние 20 действий текущего запуска; после перезапуска история пуста.
  Серии и повторяющиеся экземпляры Google исключены. Если задача уже изменилась
  после действия, отмена не затирает новую версию и показывает, что не удалось
  восстановить. Для синхронизированных задач обратные изменения проходят
  через общую очередь Google.
- **Разбор ошибок синхронизации.** В настройках видны конкретная задача,
  операция и понятная причина ошибки. Можно открыть задачу, повторить
  остановленную отправку или заново подключить Google. Повтор доступен только
  для актуальной и безопасной операции; конфликты и ошибки данных требуют
  проверки задачи. Отложенные автоматические попытки отмечены отдельно.
  Ошибки серий по-прежнему разбираются в соответствующих разделах настроек.

## Безопасность

**Не коммитьте секреты и локальные данные.** OAuth-токены, `client_secret*.json`,
`*.db`/`*.sqlite`, `.env`, логи и профили закрыты правилами в
[`.gitignore`](.gitignore) — не добавляйте их через `git add -f`.

Держите client secret и токены только в каталоге профиля. Для первого
подключения используйте **тестовый** Google-аккаунт.

## Синхронизация с Google Calendar

После подключения Google Calendar **автосинхронизация включена по умолчанию**.
Добавление, редактирование, перенос и удаление задач запускают синк примерно
через секунду после последней правки. Пока приложение открыто, изменения из
Google проверяются раз в минуту; первый цикл запускается после загрузки окна.
Статус виден в боковой панели и настройках, успешные фоновые циклы не отвлекают
всплывающими уведомлениями.

Переключатель в настройках отключает автосинхронизацию; выбор сохраняется
после перезапуска. Ручной запуск также доступен:

* кнопка «Синхронизировать сейчас» в настройках, либо
* `python -m scripts.desktop_calendar_sync_once --real-google`

Один цикл — это push локальной очереди операций, затем инкрементальный pull
по `nextSyncToken`. При сетевой ошибке изменения остаются в очереди, а повтор
откладывается на 5 секунд с увеличением задержки до 5 минут. **Закрытое
приложение не синхронизируется**: ожидающие изменения сохраняются и отправятся
после следующего запуска при включённом автосинке и доступном Google.
Задачи без даты остаются локальными; отметка «выполнено» — локальная и события
в календаре не трогает. Первый вход через браузер всегда запускается вручную.

Настройка и правила безопасности маппинга —
[`GOOGLE_SYNC_SETUP.md`](planner_desktop/docs/GOOGLE_SYNC_SETUP.md).
